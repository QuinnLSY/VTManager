| 1.0.2-r3（功能：remux 缓存「关闭即删」，无版本号变更） | 2026-09-01 | **背景**：用户反馈「每打开一个视频都会把原大小的文件存进 cache」。调研确认——`cache/remux/` 存的是 MKV/AVI/RMVB 等非 MP4 容器（moov=unknown）播放时 `-c copy +faststart` 生成的**与原视频等大的转封装副本**（moov 在尾部的 MP4 播放失败时兜底也会生成），此前**无任何自动删除机制**（仅 2GB 总量上限兜底）；而图片预览（previews）是 ≤2048px 降采样 WebP 并非原大小。**实现**：① 新命令 `cleanup_remux(path)`（`stream.rs::cleanup_remux`）——双保险定位删除：JOBS 任务记录的精确副本路径（会话内 mtime 变过也能删到）+ 当前 (path, mtime) hash 副本；顺带删除同 hash 的 `.tmp*` 残留（转封装进行中删除会让 ffmpeg 写失败自然退出，无副作用），并移除 JOBS 记录防下次播放误判 done。只动缓存、不触碰本地原文件。② **清理时机**（前端 `store::cleanupRemuxCache`，静默不阻塞）：VideoPlayer 关闭（closePlayer）与卸载（onBeforeUnmount 兜底）、主窗口/独立 PiP 窗口内**切换视频**时（删上一部）；**PiP 退出不删**（主窗口要续播同一副本）。③ **开关 `cleanup_remux_on_close`（缺省开）在「后端」读 settings 表判断**——因为 PiP 独立窗口（pip-main.ts 独立入口）的 store.settings 未加载，前端判断会不一致；设置面板「播放与查看」新增二态开关。④ Rust 单元测试 `cleanup_remux_deletes_cache_and_rebuilds`（真实 ffmpeg 端到端：生成→删除→记录清除→重复清理 no-op→重建 faststart 副本），回归总数 90 项全过。**取舍说明**：副本删除后重播同一 MKV 需重新转封装（秒级，有进度条）；用户可在设置中切「保留副本（重播秒开）」 |
| 1.0.2-r4（修复 + 缓存瘦身，无版本号变更） | 2026-09-02 | **修复① 全屏内切换条目后退出全屏，主窗口播/看的是切换前那个（视频与图片同因同修）**：独立全屏（PiP）窗口通过 `set_pip_state` 持续回写 index/进度/旋转，主窗口在收到 `pip-closed` 后 `take_pip_state` 取回。**根因是 Rust `Destroyed` 事件里 emit 之后立刻同步删除了 PipStateStore 条目**——主窗口要「收到事件 → 发一次 IPC → 执行 take」必然慢于同线程紧随其后的删除，于是 `take_pip_state` **永远返回 null**，主窗口走兜底分支回退到进入全屏前的 index。修复：回传状态改为 **窗口销毁后延迟删除**（`purge_pip_state_later`，15 秒宽限期，且只删「销毁后未被刷新过」的条目，避免极端时序下误删同名 label 的新状态）；`PipStateStore` 值改为 `(Instant, PipState)`，`set_pip_state`/开新窗口时顺带 sweep 超过 5 分钟无人取回的条目做兜底，防应用直接退出时泄漏。前端补一道防御：`openPipFromCurrentModal` 打开新全屏窗口前清空 `store.pipResult`，否则本次若取回失败会把**上一次**会话的 index/进度当成本次结果来恢复。**修复② 缓存瘦身**：`preview_image` 由 2048px/q88 降为 **1600px/q74**（`PREVIEW_MAX`/`PREVIEW_QUALITY` 常量），`image_thumb` 质量 80 → **70**（`THUMB_QUALITY`，尺寸仍 480）；实测合成照片图预览体积 121KB → 47.4KB，**减少 60.8%**（单测 `preview_cache_is_at_least_half_smaller_than_legacy` 锁定"≤旧方案 50%"，防后续调参回退）。**新增③ 缓存按时间自动过期**：`cache.rs` 新增 `touch_cache_file`（命中即把 mtime 刷为当前时间）/ `sweep_expired_cache`（删除 mtime 超过保留时长的文件）/ `maybe_sweep_expired_cache`（自限频 60s，可挂高频路径）；判定用 **mtime 而非 atime**（macOS APFS 的 atime 更新不可靠、可能被 noatime 关闭），也**不用内存表**（为的是跨应用重启仍然准确）。命中续期挂在 `image_thumb`/`video_thumb`/`preview_image` 三个唯一入口。**remux 副本不参与按时间过期**——它可能正在被播放，删了会让流式播放中断，其生命周期仍由 r3 的「关闭即删」+ 2GB 总量上限兜底。触发点：打开资料库（无条件扫一次，清掉几天没用留下的缓存）、`maybe_trim_cache`（缩略图生成路径）、`disk_usage`（设置面板查占用时顺带清理，展示的数字即最新值）。新 settings 键 **`cache_ttl_hours`**（1/6/24，**缺省 1 小时**；`0` = 永不自动清理），设置面板「存储空间」新增四态选择（点选即写入，后端 `set_setting` 立即同步，无需点「保存设置」）。新 Rust 单测 5 项（压缩比 / 命中续期 / 小图不建缓存 / 过期删除含"临时文件与 remux 必须保留"的反例 / touch 后不被清理），Rust 全量单测 10 项全过，mock 全量回归 90 项全绿 |

## 2. 数据目录布局（资料库根目录下）

```
.VTManager/
├── vtmanager.db        SQLite 数据库（唯一结构化数据源）
│                       （r13+ WAL 模式：伴随 vtmanager.db-wal / vtmanager.db-shm，
│                        迁移/拷贝时三个文件必须一起复制）
├── covers/             封面文件，命名 <hash16>.jpg
│                       hash = DefaultHasher(目标路径 + 保存时间戳)
├── cache/thumbs/       自动缩略图缓存，命名 <hash16>.webp（1.0.2+；此前为 .jpg，旧残留可清除）
│                       hash = DefaultHasher(文件路径 + mtime_ms)
│                       【可整目录删除，应用会按需重建】
├── cache/previews/     图片查看器预览缓存（r13+），≤1600px WebP（1.0.2-r4+；此前 2048px）
│                       hash = DefaultHasher(文件路径 + mtime_ms)
│                       【可整目录删除，应用会按需重建】
├── cache/remux/        视频转封装缓存（moov 前置 faststart 副本，r9+）
│                       【可整目录删除，播放时按需重新转封装】
├── cache/scrubs/       视频进度条悬停帧预览精灵图（1.0.2-r5+），WebP 网格
│                       hash = DefaultHasher(文件路径 + mtime_ms)
│                       【可整目录删除，再次悬停时按需重新生成】
└── .trash/             回收站暂存，命名 <id>_<原名>
                        id = <now_ms>-<hash16>

另：资料库根下另有 `captures/`（1.0.2-r7+）——播放器「当前帧截图」的**默认保存目录**，与 `.VTManager/` 平级（非隐藏）；可在播放器 CC 菜单「截图保存目录…」改到任意位置（记忆于 localStorage `vt_capture_dir`）。截图是用户产物，不参与缓存清理。
```

**重要约定**
- 除 `.VTManager/` 外，应用不会在任何位置写入数据；卸载/迁移只需拷贝整个硬盘（r13+ 需连同 `vtmanager.db-wal`/`vtmanager.db-shm` 一起拷贝）。
- `cache/thumbs`、`cache/previews`、`cache/remux` 均属可再生缓存，升级时无需迁移；r13+ 缓存总量超过 2GB 时应用会自动清理最旧缓存，设置面板也可一键清除。
- **1.0.2-r4 起缓存按时间自动过期**：`thumbs`/`previews`/`scrubs` 中超过保留时长（设置 `cache_ttl_hours`，缺省 1 小时；`0`=永不）未被再次访问的文件自动删除 —— 判定依据是**缓存文件的 mtime**（命中缓存时 `cache::touch_cache_file` 会刷新它），因此跨应用重启仍然准确。`remux` **不参与**按时间过期（可能正在播放，删除会中断播放），只受 r3「关闭播放器即删」与 2GB 总量上限约束。新增任何读取缓存的入口都必须记得在命中路径 touch，否则该缓存会被误判为"久未访问"。
- `covers/` 必须与数据库 `covers`/`dir_meta` 表一起迁移。
- 缩略图 hash 含 mtime：文件内容变化后旧缩略图自动失效。

## 3. 数据库 Schema（v1.0.0 基础 + r4/r8/r9/r11 增量，详见版本记录）

```sql
-- 封面索引：目录封面 / 视频封面
CREATE TABLE covers (
  path TEXT PRIMARY KEY,     -- 目标目录或视频的绝对路径
  kind TEXT NOT NULL,        -- 'dir' | 'video'
  cover_file TEXT NOT NULL,  -- covers/ 下的文件名
  source TEXT,               -- 'frame' | 'upload' | 'tmdb'
  frame_time REAL,           -- 截帧时间（秒，source=frame 时）
  updated_at INTEGER         -- epoch ms
);

-- 目录电影元数据（TMDB 刮削结果）
CREATE TABLE dir_meta (
  path TEXT PRIMARY KEY,
  title TEXT, year INTEGER, overview TEXT, rating REAL,
  tmdb_id INTEGER, poster_file TEXT,   -- poster 同时写入 covers 表
  extra TEXT, updated_at INTEGER       -- extra 为保留扩展字段(JSON)
);

-- 全盘搜索索引（扫描重建）
CREATE TABLE index_entries (
  path TEXT PRIMARY KEY,
  parent TEXT NOT NULL,
  name TEXT NOT NULL,
  name_py TEXT,              -- 拼音全拼（含原字符小写）
  py_initial TEXT,           -- 拼音首字母
  is_dir INTEGER NOT NULL,
  kind TEXT NOT NULL,        -- dir|video|image|audio|doc|other
  ext TEXT, size INTEGER,
  created_at INTEGER, modified_at INTEGER
);
CREATE INDEX idx_index_parent ON index_entries(parent);
CREATE INDEX idx_index_name ON index_entries(name);

CREATE TABLE favorites (
  path TEXT PRIMARY KEY, name TEXT NOT NULL, added_at INTEGER,
  cat_id INTEGER NOT NULL DEFAULT 0     -- r11+：收藏夹分类（0=根目录；旧库由 migrate() 自动补列）
);
-- 收藏夹分类（r11+）
CREATE TABLE fav_categories (
  id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL UNIQUE, created_at INTEGER
);
CREATE TABLE trash_items (
  id TEXT PRIMARY KEY, orig_path TEXT, trash_path TEXT,
  name TEXT, is_dir INTEGER, size INTEGER, deleted_at INTEGER,
  expire_at INTEGER  -- 1.0.2-r6：自动清除到期时刻（ms；0 = 永不）；旧库由 migrate 检测后 ALTER TABLE 补列
);
CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT);
CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT);  -- last_scan 等
```

| `sort_v2` | JSON `{"active":"name","dirs":{...}}` | 全局排序状态（r6+，含三方式各自方向记忆）；旧 `sort_key`/`sort_asc` 已废弃不再读写 |
| `theme` | `light`(默认)/`dark` | 界面主题（1.0.1+，r8 起与全部设置同存 prefs.json） |
| `trash_ttl_days` | 数字（默认 3，0–365，0=永不） | 回收站自动清除天数（r6+） |
| `cache_ttl_hours` | 数字（默认 1，0–8760，0=永不） | 缓存按时间过期保留时长（r4+；r8 起支持自定义小时输入） |
| `cleanup_remux_on_close` | `1`(默认)/`0` | 播放器关闭/切换时删除 remux 转封装副本（r3+） |

## 4. 平台解耦层（sys.rs）

平台差异集中在 `src-tauri/src/sys.rs`，新版本添加平台相关逻辑时必须继续收敛在此：

| 能力 | macOS | Windows |
|---|---|---|
| 默认应用打开 | `open <path>` | `cmd /C start "" <path>` |
| 指定应用打开 | `open -a <app> <path>`（app=.app 路径/名称） | exe 直接 spawn；.lnk 先经 PowerShell WScript.Shell 解析目标 exe |
| 定位文件 | `open -R <path>` | `explorer /select,<path>` |
| 已安装应用 | 扫描 /Applications、/System/Applications 等目录的 .app | 递归扫描开始菜单（ProgramData + APPDATA）的 .lnk |
| 资料库卷根检测 | exe 祖先中 `/Volumes/<vol>` | exe 所在盘符根（`ancestors().last()`） |
| 隐藏文件 | 名字以 `.` 开头 | hidden 属性位 + desktop.ini + `.` 前缀 |
| 文件名非法字符 | `/ \ : NUL` | 另加 `* ? " < > \|` |
| ffmpeg 解析 | `ffmpeg` | `ffmpeg` → `ffmpeg.exe` |

## 5. 内部约定（升级需保持）

- **路径同步**：重命名/移动时 `db::rename_refs()` 用 SQL `substr` 前缀替换同步 index_entries / covers / dir_meta / favorites；删除时 `db::remove_refs()` 清理。任何新增「以路径为主键」的表都必须加入这两个函数。
- **回收站**：删除 = `fs::rename` 到 `.trash/` + 记录 trash_items；恢复时若原父目录不存在会自动重建，重名自动加 ` (n)` 后缀。**r6 起支持自动清除**：条目带 `expire_at`（删除时刻 + `trash_ttl_days` 设置天数，缺省 3，0=永不）；`sweep_trash`/打开资料库/列回收站时清扫到期项（真删文件 + 删记录）；改设置按当前时刻重置全部在站条目的到期时间。
- **assetProtocol scope**：`tauri.conf.json` 中为 `{ allow: ["**"], requireLiteralLeadingDot: false }` —— **必须保留 `requireLiteralLeadingDot: false`**，否则 `.VTManager` 点开头目录下的缩略图/封面会被 asset 协议 403。前端用 `convertFileSrc` 加载本地图片/视频。
- **capabilities**：`src-tauri/capabilities/default.json` 声明 `core:default` + `core:window:allow-is-fullscreen` + `dialog:default`。新增插件或 window API 时必须同步在此追加权限，否则插件命令会被静默拒绝（1.0.0 曾因缺失此文件导致所有系统对话框失效）。
- **播放器/查看器满屏（r12+）**：满屏是组件级状态 `store.mediaFullscreen`，**不要**再调 `window.setFullscreen` 切换窗口原生全屏；关闭 player/viewer 的所有路径（关闭按钮、删除、closeTopModal）必须复位该状态。
- **前端 localStorage 键**：`vt_sidebar`（侧边栏收起）、`vt_tl_newest`（时间轴排序）、`vt_progress`（r12+ 播放进度 map，可再生）、`vt_capture_dir`（r7+ 播放器截图保存目录，可再生）。
- **前端资源嵌入**：`generate_context!` 在 `commands.rs`（lib target）中，重新打包必须 `touch src-tauri/src/commands.rs`（package-macos.sh 已内置），否则前端改动不会进入二进制。
- **修改时间语义（r7+）**：重命名/移动/从回收站还原/标记颜色/智能归类等管理操作完成后，后端会 `util::touch_now()` 把目标 mtime 刷新为操作时刻（播放/查看、修改封面除外）。未来新增文件操作类命令时保持该行为，否则「按修改时间排序」不反映最新操作。
- **扫描**：r13+ 为**增量扫描**（按 `(path, modified_at)` 快照对比：未变跳过、变化更新、消失清理），首次扫描退化为全量插入；`dir_sizes` 每次全量重建。若未来需要更细粒度，可基于 mtime 秒级精度做进一步优化。
- **搜索索引在扫描前不可用**：收藏/浏览/封面不依赖索引；搜索、最近添加、统计依赖。前端在设置中提供手动扫描入口。
- **缓存管理（r13+/1.0.2）**：`cache/thumbs`、`cache/previews`、`cache/remux` 均为可再生缓存；缩略图/预览自 1.0.2 起为 WebP 格式（有损编码走 `webp` crate/libwebp，`image` crate 的 WebP 仅无损）；总量超 2GB 自动清理（优先级 thumbs > previews > remux、最旧优先，`cache.rs::maybe_trim_cache` 每 64 次生成采样检查）；设置面板「存储空间」可一键清除（`clear_cache` 命令保留目录本身、跳过正在写入的临时文件），并有 `optimize_db`（VACUUM 压缩数据库）与「应用本体大小」展示。新增涉及缓存目录的命令时保持此约定。
- **目录列表缓存（1.0.2+）**：`list_dir` 结果经 `cache::cached_listing`/`store_listing` 走 3 秒 TTL 内存缓存（上限 64 条）。**任何新增的「写文件系统」命令成功后必须调用 `cache::invalidate_dir_cache()`**，否则列表可能短暂显示旧数据；扫描开始/完成、fs_watch 外部变更、换库也需失效。
- **视频处理主路径（1.0.2+）**：视频元数据探测与截帧优先走 `av.rs`（macOS AVFoundation，objc2 绑定），失败才回退 `media.rs` 的 ffmpeg/ffprobe 调用；发布包只分发 ffmpeg（转封装/兜底），**不再分发 ffprobe**。新增视频相关处理时保持「AVFoundation 优先、ffmpeg 兜底」的链路。
- **serde 字段命名（1.0.2+）**：Tauri 命令返回结构体默认用 `#[serde(rename_all = "camelCase")]` 匹配前端 TS 类型；**命名敏感的字段（如 `app_bytes`）需与前端 `src/api.ts`/组件读取的字段名逐一核对**（曾因后端输出 snake_case、前端读 camelCase 导致展示为 0 的 bug）。
- **字幕链路（1.0.2-r7+）**：探测只认同目录同名前缀的 `.srt`/`.vtt`（精确同名优先）；读取统一输出 UTF-8（GBK 仅作最后回退）；解析在纯前端 `src/subtitles.ts`。新增「以路径为主键」的字幕相关表/缓存时同样需加入 rename_refs/remove_refs 与缓存清理。PiP 全屏窗口只消费 `PipPayload.subtitle` 快照，不做写回。

## 6. 升级操作流程（供 v1.x → vNext 参考）

1. schema 变更：在 `db.rs` 的 SCHEMA 追加 `CREATE TABLE IF NOT EXISTS ...`（SQLite 支持增量建表）；破坏性变更需写迁移函数（读取旧表 → 转换 → 写新表 → drop 旧表），并在 `meta` 表记 `schema_version`。
2. 新增 Tauri 命令：`commands.rs` 增加函数并注册到 `generate_handler![]`；前端在 `src/api.ts` 对应增加封装。
3. 平台差异：一律进 `sys.rs`，用 `#[cfg(target_os = "...")]` 分支。
4. 发布前：本机实测（浏览/搜索/拖拽/封面/播放/回收站），清理 `cache/thumbs` 后二次实测缩略图重建。
5. 在「版本记录」追加条目。

## 7. 已知限制（v1.0.0，升级候选）

- HTML5 播放器不支持 MKV/RMVB 等容器（应用内会提示改用外部播放器）
- 搜索/最近添加/统计依赖索引扫描完成；扫描期间结果不完整
- HEIC 图片依赖 macOS 系统解码，Rust 缩略图可能生成失败（会回退占位图标，不影响查看）
- TMDB 刮削为电影（movie）类型，剧集（TV）暂未支持
- 换电脑迁移时如应用本体签名变化，macOS 可能需右键打开一次
